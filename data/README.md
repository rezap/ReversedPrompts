# Evaluation corpus and pair set

The first pair corpus for the induction system. One document, twenty
`(prompt, output)` pairs, all sharing the same input.

```
data/
  corpus/agentic-ai-survey.md        the input content, I
  pairs/agentic-ai-survey.jsonl      20 records
tools/
  pdf_to_markdown.py                 PDF -> markdown, reproducible
  build_pairs.py                     authors the JSONL; --check guards drift
```

## The document

Schneider, J. (2025). *Generative to Agentic AI: Survey, Conceptualization, and
Challenges.* [arXiv:2504.18875v1](https://arxiv.org/abs/2504.18875), 54 pages,
CC-licensed preprint. Converted to markdown at ~20,000 words with the section
tree, all four tables, and figure captions preserved. Figures themselves are
dropped; captions remain, so figure references in the text resolve to something.

Regenerate with:

```
python tools/pdf_to_markdown.py 2504.18875v1.pdf data/corpus/agentic-ai-survey.md
```

Conversion is deterministic — rerunning reproduces the committed file byte for
byte. Fidelity against raw text extraction is ~96% of words; the ~850-word
difference is page numbers, the arXiv stamp, and the dot-leader table of
contents, which is replaced by a clean list rebuilt from the PDF outline.

## Record schema

| Field | Meaning |
|---|---|
| `id` | `{category}-{nn}` |
| `category` | `fetch` \| `summarize` \| `reason` |
| `input_ref` | path to the corpus file |
| `input_sha256` | digest of the corpus this output was generated against |
| `target_prompt` | **the gold** — what induction must recover. Never shown to the inducer. |
| `output` | generated by running `target_prompt` against the full corpus |
| `output_shape` | `prose` \| `list` \| `table` |
| `gold_sections` | hand-labelled: which parts of the input the output actually drew on |

## Design decisions

**Every pair takes the whole document as input.** Not a pre-selected section.
This is the honest form of "fetch facts from parts of a document", and it is
what makes the `selection` facet measurable: with `I` held constant across all
twenty pairs, every difference between outputs is attributable to the prompt.
It also means the retrieval policy has real work to do — an answer drawing on
two paragraphs of a 20,000-word input is a precision problem, not a
summarization one.

**`gold_sections` is a hand-labelled alignment map.** It is not used for
generation or scoring at Tier 1; it exists so the Align stage can be evaluated
directly in Phase 2 rather than only through its downstream effect on output
quality.

**Categories are reported separately, never pooled.** Compression ratios differ
by roughly 6x between `fetch` (1.9–6.3 words out per word of prompt) and
`reason` (7.7–17.2). Any metric averaged across all twenty is dominated by the
reasoning pairs and says little about either group.

**Some prompts carry checkable constraints** — exact sentence counts, word
budgets, column limits, required orderings. `tools/build_pairs.py` was validated
against these, so a recovered prompt that drops a constraint produces a
measurably non-conforming output. That gives Tier 1 something deterministic to
grip beyond style features.

## Provenance and its limits

Both halves of every pair were written by the same model in one session: the
prompts first, then the outputs by running those prompts against the document.
Outputs are faithful targets — checked against the source, with quoted figures
verified to appear in the corpus — not deliberately corrupted.

The limitation this creates is worth stating plainly, because it bounds what a
good score here means. Pairs authored this way are more tightly aligned than
prompt/output pairs collected from real usage, where outputs routinely overshoot
or undershoot what was asked. Prompt reversal will look easier on this set than
on production data, and **Tier-1 metric weights calibrated here should be
treated as provisional** until they can be re-tuned against pairs with
independent provenance.

What the set does test soundly is the core reversal problem: the inducer never
sees `target_prompt`, so recovering it from `(I, O)` is a genuine inference in
both cases. The optimism is in the difficulty, not in the validity.

Noise lives on the input side by design — the full document is ~95% irrelevant
to any single pair — rather than in the outputs.
